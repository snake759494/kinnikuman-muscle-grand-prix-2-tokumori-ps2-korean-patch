# 기술 설명

## 디스크 구조
- 게임 데이터는 `DATA.BIN`(LBA 278) 하나의 AFS 아카이브. 항목 이름은 첫 항목 `packfile.bin`(FLST)에 있다(`tools/filelist.tsv`).
- 항목 안은 `PACK` 컨테이너가 여러 겹 중첩되고, 그 안에 CXML(`.cxm`), XML, PFNT 글꼴(`.pft`), 텍스처(`.gs`)가 들어 있다.
- 재패킹: AFS 항목 크기가 바뀌면 DATA.BIN 전체를 다시 쓰고 뒤따르는 ISO 파일을 새 위치로 옮긴다. FLST의 크기 표도 0x800 단위로 갱신한다.

## 문자열
- CXML: `'CXML'` 헤더 0x10 + 24바이트 노드(name, value, parent, child, next, ?) + 문자열 풀. 노드를 그대로 두고 풀만 다시 만든다.
- 문자열은 Shift-JIS. 커맨드 리스트의 기호(打·組·必·Ｇ)는 번역하지 않는다.
- 캐릭터별 커맨드 데이터는 `pack\char*.bin` 156개에 따로 있다(cmd##.cxm).
- 실행파일(SLPS_258.81) 안의 문자열 392개(스테이지 이름 등)는 원래 칸 크기 안에서 바꾼다.
- 줄바꿈 문단(컬렉션 해설)은 글자 폭 표를 읽어 원래 줄 수·폭에 맞춰 자동으로 줄을 나눈다.

## 한글 글꼴
- PFNT(`font/font.pft`, `font/collection_font.pft`)에 한글 2,350자(KS X 1001)와 번역에 쓰인 확장 음절을 그려 넣는다.
- 한글은 Shift-JIS 한자 영역 0x889F부터의 코드에 차례로 대응시킨다. 스태프롤 인명과 커맨드 기호에 쓰는 한자는 남긴다. 두 글꼴이 같은 대응표를 쓰도록 남길 한자 목록을 공유한다.
- 서체는 원본의 굵은 명조체와 비슷한 서울한강체 EB.

## 그림 글자
- `.gs` 텍스처(0x80 헤더, PSMT4/PSMT8 + 팔레트)를 풀어 글자 영역을 OpenCV inpaint로 지우고 한글을 그린 뒤 원래 팔레트로 다시 양자화한다.
- 캐릭터 이름판(Cn_*, 256x32)은 같은 이름이 캐릭터 팩마다 다른 이미지로 들어 있어, 픽셀 유사도로 가장 가까운 기준 이미지를 찾아 이름을 정한다.
- VS 화면 별명 문구(Nn_*)는 텍스처가 180° 뒤집혀 있고 세로쓰기용으로 글자마다 90° 돌아가 있어, 글자를 하나씩 돌려 그린다.
- 원본 텍스처의 MD5로 교체 대상을 찾으므로 같은 그림이 여러 팩에 있어도 한 번에 바뀐다.

## 16:9 와이드 패치 (PCSX2)
- `SLPS-25881_2ABD62D3.pnach`: PCSX2 내장 와이드 패치(El_Patas, 원본 CRC D5FDEBDC)를 한글판 ELF CRC(2ABD62D3)에 맞춰 옮긴 것. 0x1C5DEC의 `lui at,0x4420`을 `0x4455`로 바꿔 가로 시야를 넓힌다.
- 한글 패치가 ELF 문자열을 고쳐 CRC가 바뀌므로 내장 패치는 자동 적용되지 않는다. 패치 주소는 한글 패치와 겹치지 않음(한글판에서도 원래 값 `3C014420` 확인).
- 3D 화면만 넓어지고 2D 그림은 가로로 늘어나 보인다.
